## Executive summary

sigma-predict is a well-architected single-developer forecasting pipeline (clean stage separation, strong contamination-control DESIGN, 143 passing tests, clean bandit scan) that is NOT production-ready. The headline failure is a CRITICAL human-in-the-loop integrity defect: the Streamlit Predict page calls orchestrator.predict(auto_submit=True), which submits to the live platform AND persists the record with reviewed=False BEFORE the human review form is even rendered (confirmed by direct code read at pages/2_Predict.py:72-78 + orchestrator.py:485-499). The reviewer's Accept/Adjust/Reject decision is recorded locally but cannot affect the already-submitted probability — Reject cannot un-submit, Adjust never reaches the platform. The fix is trivial and the correct APIs (predict_until_review + submit_after_review) already exist and are documented for exactly this UI flow; three stale TODOs falsely claim they are 'not yet finalised'. This single fix resolves five merged findings.

The second systemic theme is a class of silently-inert features that undermine the product's core value (correct, calibrated, auditable forecasts) while appearing to work — independently surfaced by the biz-logic, methodology, critic, and readiness passes that the framed audits largely missed: (1) Phase-2 Platt calibration is structurally unreachable because fit_platt/save_platt_params are never called in production, so the documented '3-phase' calibration tops out at isotonic; (2) the search-augmented temporal firewall is a no-op (SearchResult has no date field) yet injects a false 'temporal firewall applied' claim into the LLM prompt; (3) extremization never fires under the default single-provider config though the method is named 'extremized_trimmed_mean' and a 1.5 factor is configured; (4) the community-divergence human-review safety flag is permanently dead because the producer writes key 'metaculus' while the consumer reads 'metaculus_community'; (5) anomaly_detected/cross_platform_divergence are declared and surfaced in review UI but never computed; (6) the deliberation_stdev_threshold config knob is dead. A genuinely high-impact methodology bug: calibration is FIT on submitted (post-calibration, human-adjusted) probabilities but APPLIED to the raw pre-calibration aggregate — a domain mismatch that silently degrades the central calibration claim (confirmed at query.py:116-119 + orchestrator.py:337-340).

The third theme is missing production scaffolding entirely orthogonal to code quality: zero retry/backoff on any external call, no CI, no lockfile, no README, no spend ceiling, 19 known CVEs (pip-audit ground truth), API keys in plain dataclass fields, and a global cache_resource singleton bridge that races across Streamlit sessions. None of these are caught by the test suite. Net: the math and architecture are mostly sound, but the human-review gate is cosmetic, several core features silently no-op, and operational readiness is near-zero. Roughly 8-10 fix-now items, most low-effort, stand between this and a defensible production posture.

The test suite passes but gates nothing and covers none of the orchestrator/scoring/signal-contract surfaces where the real bugs live.
- Warning channels built but not connected: warnings_out params exist on estimate_base_rate and decompose_question but the orchestrator never passes them; a local pipeline_warnings list is populated but never merged into the record. The plumbing for observability exists and is simply unwired in several places.
